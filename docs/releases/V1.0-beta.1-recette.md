# Recette V1.0-beta.1 — back-office Halloween Map

Cette fiche accompagne la prerelease `V1.0-beta.1`. Elle ne vaut pas validation de la V1.0 stable : cocher les contrôles **sur l'instance réellement utilisée** après sauvegarde PostgreSQL. Ne jamais tester une purge ou une suppression irréversible sur des données de production.

## Déploiement et retour arrière

- [ ] Sauvegarde PostgreSQL vérifiée **avant** redéploiement (et restauration testée si possible).
- [ ] `IMAGE_TAG=V1.0-beta.1` dans l'environnement de la stack ; `migrate`, `app` et `worker` utilisent le même tag.
- [ ] Migration terminée sans erreur ; `app` et `worker` démarrés et sains ; accès HTTPS fonctionnel.
- [ ] Version affichée conforme à la bêta ; accès public et authentification vérifiés.
- [ ] Ne pas supposer qu'un retour au tag précédent annule les migrations : restaurer la sauvegarde correspondante si un retour arrière de schéma est nécessaire.

## Administration Studio — contrôle manuel

- [x] **Navigation latérale** : premier retour visuel utilisateur satisfaisant sur la bêta (21/10/2026).
- [ ] **Logo** : retirer le fond rectangulaire du wordmark officiel sans altérer le dessin, les couleurs ou le contraste.
- [ ] Réduction/réouverture du menu, sélection active, thème clair/sombre, affichage mobile et clavier.
- [ ] Tableau de bord : chiffres et saison affichés cohérents avec les données réelles.
- [ ] Maisons : recherche, filtres, ouverture, validation/refus et permissions ; aucune action destructrice sur données réelles.
- [ ] Utilisateurs : liste, droits, rôles et refus d'accès avec un compte non autorisé.
- [ ] Saisons : active/test, changement de contexte, conservation des filtres et absence de mélange de données.
- [ ] Statistiques et activité : période, contexte saison et états vides.
- [ ] Communications : modèles, prévisualisation et envoi uniquement vers une adresse de test.
- [ ] Contenus courts : modification, aperçu, sauvegarde, restitution publique.
- [ ] Documents officiels : édition riche (titres, listes, liens, tableaux), aperçu mobile, brouillon privé, conflit de révision, restauration et publication **uniquement sur un document de test**.
- [ ] Vérifier la consultation publique après publication et les éventuelles règles de réacceptation.
- [ ] Contrôler la console navigateur et les logs `app`/`worker` après chaque parcours critique.

## Automatisation déjà couverte par la CI

Le workflow CI exécute lint/typecheck, tests unitaires, build, Playwright, tests HTTPS, migrations répétées et vérification de la stack Docker. Ces contrôles **ne remplacent pas** la recette sur les données et le réseau réels.

## Critères pour V1.0 stable

- [ ] Tous les parcours critiques ci-dessus validés, ou écarts documentés et acceptés.
- [ ] Anomalie visuelle du logo corrigée et contrôlée sur fond clair/sombre.
- [ ] Aucun problème bloquant sur permissions, confidentialité des brouillons, migration ou publication.
- [ ] Nouvelle CI verte après les corrections ; changelog stable, version et image vérifiés.
- [ ] Décision explicite de publier la stable ; ne pas remplacer `latest` durant la recette bêta.
